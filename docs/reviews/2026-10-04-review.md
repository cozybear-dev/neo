# Neo review — 2026-10-04

**Implementation follow-up:** findings below describe the reviewed baseline. Current fixes, verification, and enforced capability limits are tracked in the [remediation status](../plans/2026-10-04-remediation.md).

The project has a useful plugin structure and a passing test baseline, but its current runtime does not deliver several advertised isolation and workflow guarantees. The highest-priority work is to constrain Docker access, enforce task scope at execution boundaries, repair browser/OAST/deployment integration, and make shared state safe under concurrency.

This review records **30 findings and four improvement workstreams**. The [remediation plan](../plans/2026-10-04-remediation.md) maps every item to implementation work and acceptance checks. No application fixes were made during the review.

## Findings

### F01 — P1 — Raw Docker sockets defeat the claimed isolation boundary

**Code.** `docker-compose.yml:49` and `:74` mount the host Docker socket into both `dsh` and `sandbox`. `docker/dsh/Dockerfile` has no non-root `USER`; the profile enables `danger-full-access` and approval `never`. The sandbox's `neo` user has passwordless sudo (`docker/sandbox/Dockerfile`). Comments claiming “exec only” or “targets only” do not constrain Docker API requests. Arbitrary agent shell code can reach host-level container-management capabilities.

Remove sockets from general-purpose agent containers. Put the necessary operations behind a narrowly constrained execution/deployment broker, with fixed sandbox identity, ownership checks, approved network/mount policy, and isolated credentials. Simply installing Docker in the current harness would make the existing deployment path work without fixing this boundary.

### F02 — P1 — Scope checks do not guard all network-producing operations

**Code; replay redirect reproduced.** `plugins/neo-sandbox-docker/src/client.ts:288` executes arbitrary shell commands without a scope check. Browser scope checking happens only in `browserNavigate` (`plugins/neo-tools-browser/src/client.ts:561`); redirects, subresources, clicks, and evaluated JavaScript are unrestricted. `plugins/neo-tools-traffic/src/client.ts:180` neither checks current task scope nor prevents redirects.

A local replay fixture followed a 302 to another destination port and contacted it successfully. A preliminary `scope_check` cannot authorize everything an arbitrary command or page later contacts. Enforce scope using task-bound execution/network policy, including redirects, secondary requests, resolved addresses, and excluded destinations. Treat prompt instructions as guidance rather than the enforcement mechanism.

### F03 — P1 — Scope identity and authorization can be changed or lost

**Reproduced and code.** `/scope/check` falls back to the environment allowlist when a supplied, valid UUID has no task row (`control/src/server.ts:487`). A probe using a random nonexistent task returned `200 {allowed:true}`. Existing tests explicitly encode this behavior; it is a policy/design defect rather than a failing test. Task creation and `task_update` accept replacement allowlists without server-side approval provenance. The control API has no authentication, and explicit task IDs are trusted.

Fail closed for missing/invalid task identity; bind credentials/capabilities to a task and require a separately recorded authorization change to expand its scope. Specify whether the environment list is a ceiling or an additive grant: currently task and environment lists are unioned. Define supported target syntax. The pentest form advertises CIDRs, but the matcher implements hostname globs, not CIDR membership or path exclusions.

### F04 — P1 — Default host exposure includes a database with known credentials

**Code.** Compose publishes `5432:5432` using `neo/neo`, and `3080:3080` while the profile binds the harness web server to all interfaces (`docker-compose.yml:56`, `:122`; `plugins/neo-profile/cordis.patch.yml`). The README sends users to loopback, but that does not restrict published interfaces. Firewall behavior was not evaluated, and upstream UI authentication was not audited.

Remove the database host port by default, bind local UI access explicitly to loopback, and require independently configured credentials/authentication for intentional remote access. Prevent target/sandbox-origin requests from directly administering the control API.

### F05 — P1 — Deployment's network override does not sandbox an input Compose stack

**Reproduced by configuration resolution; no unsafe stack launched.** `plugins/neo-tools-deploy/src/client.ts:165` adds top-level network definitions but never validates or rewrites service settings. `docker compose config` retained a fixture's `network_mode: host`, `privileged: true`, published port, and Docker socket bind mount when merged with this exact override. Explicit additional networks also remain possible.

Resolve the complete input configuration before execution, reject unsupported or dangerous service/build/include settings, and generate an approved deployment spec. Validate the effective configuration again at the broker boundary. This must ship before enabling the currently broken deployment runtime.

### F06 — P1 — Deployment executes in a container without Docker/Compose

**Reproduced and code.** `deployUp` uses local `nodeSpawn('docker', ...)` (`plugins/neo-tools-deploy/src/client.ts:124`, `:217`), so it runs in `dsh`, not through `sandbox_exec`. Neither the DSH Dockerfile nor the sandbox Dockerfile installs Docker/Compose. `command -v docker` returned absent in both images. Deployment and the Docker-exec CLI fallback cannot work through these paths.

Route deployment through the constrained broker from F01/F05 and make executable/version availability a startup capability check. Do not resolve this solely by adding an unrestricted Docker CLI to `dsh`.

### F07 — P1 — Browser health passes while CDP is unreachable to the harness

**Reproduced.** With the unchanged `docker/browser/start-chromium.sh`, browser-local `/json/version` returned 200 and Chrome 133.0.6943.16, while the same endpoint from a peer container returned `ECONNREFUSED`. The `--remote-debugging-address=0.0.0.0` argument is not producing the intended listener with this image. Compose's healthcheck only probes loopback (`docker-compose.yml:93`).

Provide an explicitly reachable, internal-only CDP endpoint, for example through a constrained proxy or a supported browser launcher. Test discovery and a WebSocket session from `dsh`, not just inside the browser container. Keep CDP off public host interfaces.

### F08 — P1 — Browser and replay cannot reach targets on the lab-only network

**Code.** `browser` and `dsh` join only `control`; Juice Shop and deployed lab services join only `targets` (`docker-compose.yml:58`, `:99`, `:160`). Browser navigation originates from Chromium, and traffic replay uses `fetch` in DSH. Neither has a route/Docker DNS membership for target-only service aliases. This remains broken after fixing CDP itself.

Provide a scoped route/proxy into lab targets for browser and replay traffic, or carefully redesign network memberships. Do not bridge target code into the control plane as an incidental fix. Verify browser navigation and replay against a target-only fixture.

### F09 — P1 — Default OAST callback URLs have no working DNS path

**Reproduced and code.** `payloadFor` derives callback domains from the API endpoint hostname (`plugins/neo-tools-oast/src/client.ts:213`, `:290`). With the default configuration it emits `<id><nonce>.interactsh`, while the server is configured with `oast.neo.internal`. Compose supplies neither wildcard DNS for these subdomains nor a target resolver pointing to the OAST server. The generated callback URL failed with `ENOTFOUND` in the dedicated review network.

Separate API endpoint, callback suffix, and callback transport/port. Configure a real internal DNS path for the lab mode and validate callbacks from the target network. Return a clear unsupported result for DNS OAST when no suitable resolver/domain is configured.

### F10 — P1 — OAST nonce generation is incompatible with Interactsh 1.4.1

**Reproduced against the installed `latest` image, version 1.4.1.** One alphabet is used for both correlation ID and nonce (`plugins/neo-tools-oast/src/client.ts:69`, `:80`, `:214`). The server now requires the nonce to use z-base-32. A callback with nonce `0000000000000` produced zero interactions; the same registered-client procedure with `bbbbbbbbbbbbb` produced one correctly decrypted interaction. Generated nonces containing unsupported characters silently disappear.

Use the protocol's separate alphabets and pin a compatible server version/digest. Keep an actual server callback test, not only tests using the client's own encryption helper. The alphabet restriction is explicit in [Interactsh 1.4.1's server source](https://raw.githubusercontent.com/projectdiscovery/interactsh/v1.4.1/pkg/server/util.go).

### F11 — P1 — Cancelling execution leaves commands running; fallback can repeat work

**Cancellation reproduced; fallback path inspected.** The Docker client aborts the HTTP request, without terminating the remote exec process (`plugins/neo-sandbox-docker/src/client.ts:190`). A command that slept then wrote a marker still wrote it after the caller received `AbortError`. There is no execution deadline or remote process-group cleanup. `createDocker` catches broad HTTP-path errors and retries through the CLI (`:272`), even if the command may already have started. Its abort guard checks the original options signal rather than the merged signal.

Track a remote job/process group and explicitly stop it on cancellation or timeout. Preserve “outcome unknown” rather than replaying an ambiguous command. Only choose fallback before submission, and spool bounded output to artifacts instead of buffering arbitrary output in RAM.

### F12 — P1 — Concurrent partial updates lose task memory and task metadata

**Memory race reproduced; analogous task update inspected.** Memory PUT reads all fields and writes the merged snapshot (`control/src/server.ts:267`). Two concurrent updates to different keys, `{facts:['fact-A']}` and `{todos:['todo-B']}`, returned success but the final record had empty facts. PATCH task has the same read/merge/write structure (`:194`), so a status change can overwrite a concurrent scope/objective change. Issue PATCH has a similar stale-snapshot risk.

Use atomic updates for only supplied fields and optimistic revisions or explicit append/upsert operations where clients update the same list. Test synchronized concurrent requests and reject stale writes where merging is unsafe.

### F13 — P1 — Browser state and filesystem artifacts cross task boundaries

**Browser cache reproduced; artifact design inspected.** `cachedSession` is module-global and takes the first browser page (`plugins/neo-tools-browser/src/client.ts:104`, `:304`, `:550`). Two separate client configurations returned the same session and the second connection factory was never called. Cookies, current page, captured requests, traffic JSONL, screenshot directories, specialist directories, and `/workspace/plan.md`/`report.md` are shared.

Concurrent specialists can navigate away from each other's pages; separate chats can read or replay each other's evidence and authenticated requests. Give each task its own browser context, traffic store, and artifact root; separate runs of the same specialist as well. Dispose contexts on task completion and verify two-task isolation.

### F14 — P1 — Secret handling exposes credentials in files and model-visible strings

**Reproduced and code.** The entrypoint redirects mapped credentials into `.neo-llm.env` without setting permissions (`docker/dsh/entrypoint.sh:73`); the fresh review container created it as **0644**. Workspace startup and `neo-fs-workspace` broaden file readability to everyone. Key-name-based redaction leaves query strings, `postData`, command output, raw OAST requests, and credential-bearing deployment refs/logs unchanged. A fixture containing `postData: 'password=fixture-secret'` and a `?token=` URL rendered both values verbatim.

Avoid persistent shell credential exports where possible; otherwise create them atomically with 0600 and remove them after use. Use task ownership/shared groups instead of global readability. Preserve raw evidence in restricted storage and render a separately redacted view covering headers, structured/string bodies, URLs, and errors. Test secret fixtures at the model-output boundary.

### F15 — P1 — Thorough verification and planning approval are prompt conventions

**Confirmation bypass reproduced; orchestration policy inspected.** POST issue accepts the caller's `verdict:'confirmed'` without a verifier identity, verification record, or evidence (`control/src/server.ts:318`). The probe created a confirmed Thorough issue with no evidence. Omitting `task_id` also bypasses task-mode rules. Plan approval and retry limits exist in prompt text, not persisted execution policy. `assertCallerPolicy` only restricts judge children; planner child types and `readonly` are not enforced by the delegate runtime.

Persist approval and verification records, bind them to task/plan/finding revisions and run identities, and validate them before swarm execution or confirmed filing. Enforce allowed child types and actual capability policy outside the prompt. Preserve independent finder/verifier provenance rather than trusting a string field.

### F16 — P2 — Deployment cleanup loses project context and reports false success

**False success reproduced; command context inspected.** `deployDown` never reads the written metadata or original Compose files and working directory (`plugins/neo-tools-deploy/src/client.ts:286`). It calls `docker compose -p ... down` from the caller's directory, then ignores both cleanup results. A fixture where both commands returned exit 1 still returned `{ok:true}`. Partial startup failures also leave no rollback strategy.

Persist the exact effective deployment spec, project directory, service/container IDs, task owner, and lifecycle state. Tear down only those resources; validate outcomes, distinguish already absent from failed, and support retryable partial cleanup. Make volume deletion an explicit retention choice rather than unconditional `-v`.

### F17 — P2 — Deployment IDs and returned endpoints are not validated

**Path behavior reproduced; endpoint behavior inspected.** `id` is only trimmed, then inserted into workspace paths and resource names (`plugins/neo-tools-deploy/src/client.ts:205`). A probe with `../../outside` generated log and metadata writes outside the deploy directory before a real Docker command would validate its name. The returned endpoint is always `http://<id>:80` (`:278`), including Compose services that have neither that network alias nor port 80. “Started” does not imply ready.

Validate IDs before any filesystem action, resolve paths against a contained deployment root, prevent reuse/collisions, and determine endpoints from an explicit service/port configuration. Apply aliases consistently and wait for a bounded readiness check before returning a usable endpoint.

### F18 — P2 — Issue update's public tool contract cannot fulfill its promises

**Reproduced and code.** `issue_update` accepts/sends a comment (`plugins/neo-tools-issues/src/tools.ts:133`, `client.ts:181`), but PATCH issue ignores it and the schema has no comment storage (`control/src/server.ts:435`; `control/migrations/001_init.sql`). A comment update returned 200 and stored nothing. The tool also cannot supply a verdict/evidence when promoting an unverified issue to confirmed, although the API requires a confirmed verdict.

Implement a persisted, attributed comment/audit history and a verification-aware status transition contract. Reject unsupported fields rather than silently succeeding. Test through the plugin, HTTP API, and database together.

### F19 — P2 — Task mode and bootstrap depend on incidental tool order

**Code.** `.env.example:35` documents `NEO_MODE_DEFAULT`, while the orchestrator and task bootstrap read `NEO_MODE`. Task creation occurs inside memory tools (`plugins/neo-tools-memory/src/task.ts:85`) with objective `session`; scope checks and issue creation do not ensure a task exists. A fast request expressed in chat cannot update the persisted mode through `task_update`. Conversely, a valid session UUID can make `issue_create` fail with task-not-found until memory is touched.

Create a task once at session/workflow entry with validated mode, objective, and approved scope. Store it as the authoritative state used by prompts, children, issue rules, and tools. Standardize/document the environment name and define behavior for mode changes and explicit invalid IDs.

### F20 — P2 — API validation and multi-statement creation are incomplete

**Validation reproduced; atomicity inspected.** Task creation accepts non-string allowlist elements; `[null]` was stored with 201 and caused `/scope/check` to return 500. Issue severity is arbitrary, PATCH title can be empty, and malformed memory fields are silently ignored. Task and task-memory rows are inserted in separate statements (`control/src/server.ts:140`), allowing a failed second statement to leave a partial task and turn retries into conflicts.

Add request/response schemas with string/enum/length/list constraints, consistent validation errors, and explicit UUID semantics. Create related records in a transaction and add appropriate DB constraints. Include fault-injection and invalid-input tests.

### F21 — P2 — Summaries use the parent default rather than the executing agent's model

**Reproduced.** `plugins/neo-summarizer/src/index.ts:26` consults `agentDefaultModel.currentSelection()` before `exec.agent.options`. With distinct parent/workhorse models, the real registered hook selected `parent-provider/parent-model` for a workhorse tool result. This contradicts the README's routing promise and can send data/cost to the wrong configured provider.

Prefer the executing agent's resolved selection, falling back to the global default only when absent. Also preserve existing `additionalContexts` when replacing content (`summarize.ts:254`) and use a model-aware input budget instead of a universal 900,000-token ceiling. Maintain a raw artifact pointer so a failed/short summary does not discard the only accessible evidence.

### F22 — P2 — CDP fallback has protocol, lifecycle, and error-reporting defects

**New-page method reproduced; remaining paths inspected.** `/json/new` is called with GET (`plugins/neo-tools-browser/src/client.ts:450`); the shipped browser returned 405 for GET and 200 for PUT. If no page is found, the client falls back to a browser-level socket but sends page-domain methods. Navigation ignores the requested wait, errorText, and final redirected URL. Actions report success without checking JavaScript `exceptionDetails`, and a missing click selector is a no-op. Pending requests have no deadlines or close/error rejection; successful cached sessions never reconnect after disconnection.

Make the fallback equivalent to the advertised browser contract: correct target creation/attachment, bounded lifecycle waits, real failure propagation, cancellation, connection disposal, and cache invalidation. Test missing pages/selectors, navigation failure, socket loss, and timeout.

### F23 — P2 — Captured traffic is not durably finalized and write failures are unhandled

**Status mismatch reproduced; failure path inspected.** Requests are appended before response status arrives (`plugins/neo-tools-browser/src/client.ts:244`). Later handlers mutate memory only. A controlled capture showed status 201 in `browser_network` and no status in persisted JSONL. `void appendTraffic(...)` has no error handler, allowing filesystem errors to become unhandled rejections. Matching Playwright responses only by URL can misattribute concurrent requests.

Persist capture events with stable request IDs and response updates, or finalize records when responses arrive. Queue/flush writes with backpressure, report storage failure, and guarantee a coherent snapshot for replay/search. Do not silently turn disk failure into successful evidence capture.

### F24 — P2 — Replay validates relative edits but sends the unresolved URL

**Reproduced.** `assertSameDestination` resolves relative URLs for validation, but `replayTraffic` assigns the original edit string to `fetch` (`plugins/neo-tools-traffic/src/client.ts:150`, `:199`). `/relative` passes validation then fails with `Failed to parse URL`. Header editing also lacks case-insensitive replacement semantics and does not remove headers named by the `Connection` header.

Build and use one canonical URL, validate supported HTTP(S) schemes, normalize header edits, and correctly remove hop-by-hop headers. Scope and redirect enforcement belongs in F02; relative edit and header correctness need separate functional tests.

### F25 — P2 — Delegate limits and failure handling are local to a single call

**Code.** Per-preset limits and the worker pool apply only to each `executeDelegate` invocation (`plugins/neo-orchestrator/src/delegate.ts:150`, `:239`, `:489`). Nested/concurrent calls multiply total activity; there is no shared task budget/depth bound. `Promise.all` rejects on one thrown child while other workers can keep starting/running children, and the parent loses the aggregate result. Timestamp/index run IDs can collide across concurrent calls; prompts use hardcoded `/workspace` instead of the configured root. Missing subagent support yields `ok:true` with blocker records, which can be mistaken for executed work.

Use a task-level scheduler/semaphore and budgets, collision-resistant run IDs and run directories, and explicit partial/failed/unavailable outcomes. On failure, either settle every child or cancel and await siblings. Pre-create each child's artifact directory before starting it and propagate the configured task workspace.

### F26 — P2 — Advertised specialist capabilities are absent from the image

**Executable absence reproduced; optional integrations unverified.** The sandbox image lacks `gh`, Impacket, NetExec, `adb`, and `ssh`; the Dockerfile does not install them. The GitHub preset directs agents to use `gh` in the sandbox; red-team/mobile skills promise related tools. VPN recipes need networking privileges/devices that the default Compose service does not configure. Setting a hardware environment variable alone does not prove the corresponding runtime is available.

Maintain an executable/version/capability manifest and check it at startup and specialist selection. Install intentionally supported dependencies; fail closed with specific blockers for optional capabilities. Add opt-in VPN/mobile profiles with narrowly specified permissions. Validate the Ghidra extension and endpoint before advertising that profile as available; no live Ghidra conclusion was established in this review.

### F27 — P2 — Test and build entrypoints leave major behavior uncovered

**Reproduced and code.** Root `npm test` omits `control/src/server.test.ts`; that suite silently skips its DB tests if Postgres is absent. `tests/integration/modes.test.ts` asserts prompt phrases, not workflow execution. Network/deployment/OAST tests mostly use mocks. Root Node engines/setup are missing. Twelve tracked `dist` files differ from current compilation, some package entrypoints are absent until built, and source tests do not exercise those exports. Docker recompiles them, so this is not a claim that a fresh image uses stale output. There is no CI workflow in the checkout.

Provide one supported local/CI check command with an explicit Node version, mandatory disposable DB, type checks, actual compiled-package imports, and isolated service contract tests. Choose either fully reproducible committed outputs or generated-only build outputs. Keep the scripted harness test and extend it to stateful workflows.

### F28 — P2 — Locked control dependencies have outstanding security advisories

**Dependency audit.** `control/package-lock.json` resolves Fastify 5.12.1 and fast-uri 4.1.2. The audit reported two high-severity affected package entries with fixes available. This is not evidence that every advisory is exploitable through Neo: for example, the [Fastify HTTP/2 trailer advisory](https://github.com/advisories/GHSA-4mh8-r7rc-xpvc) requires features this server does not enable. URI canonicalization issues are documented in the [fast-uri advisory](https://github.com/advisories/GHSA-5jgf-p345-68v8).

Update to reviewed patched versions, refresh the lockfile, rerun API/contract tests, and track applicability rather than treating the package audit as a proven application exploit. Include image/tool dependencies in future scheduled scans.

### F29 — P2 — Builds depend on mutable artifacts and lack integrity checks

**Code.** Interactsh and Juice Shop use mutable tags. Sandbox installs TruffleHog via a script from `main`, Semgrep without a version lock, and wordlists from `master`; optional download failures are swallowed. Ghidra bridge dependencies and the extension archive lack the same integrity pinning as the Ghidra distribution. Control uses `npm install` in its Dockerfile despite having a lockfile. The Interactsh mismatch in F10 is a concrete consequence of mutable compatibility assumptions.

Pin release versions/digests and downloaded artifact checksums, use deterministic dependency installation, record an SBOM/capability inventory, and use a deliberate update workflow. Separate optional downloads from required toolchain checks so missing artifacts are visible.

### F30 — P3 — Configuration APIs and documentation have drifted

**Code/documentation.** Scope/memory/issues expose `ClientOptions.controlUrl` but construct URLs exclusively from environment values. Task-ID resolution, HTTP decoding, host normalization, and redaction are duplicated and already differ in behavior. The custom YAML parser discards blank/comment-looking lines before parsing block scalars, so adding a persona with meaningful literal lines changes its content. Agent documentation still says sandbox uses bash, lists an orchestrator preset ID different from `orchestrator`, and advertises a custom-agent manager that is absent. Compose has contradictory Docker-socket comments; the old implementation plan describes legacy settings/model behavior.

Consolidate shared contracts/helpers, honor or remove unused options, and replace or explicitly constrain the YAML subset. Refresh the runbook/capability matrix and mark historical plans as superseded where appropriate. Prefer generated capability documentation plus behavior-based tests over matching descriptive strings.

## Further improvement workstreams

### I01 — P3 — Operability and database evolution

`/healthz` always returns success after startup; request logging is disabled; pool errors and SIGTERM shutdown have no explicit handling. Migration code reruns one `CREATE TABLE IF NOT EXISTS` file with no migration ledger/version locking. Add separate liveness/readiness checks, structured redacted logs carrying task/run/request IDs, graceful shutdown, bounded DB request timeouts, migration history/advisory locking, and a tested backup/restore procedure.

### I02 — P3 — Bounded storage and query cost

Issue queries return every matching row and have no supporting task/filter/time indexes beyond primary keys. Traffic search/replay loads the whole JSONL file; browser arrays and OAST session maps grow without retention or cleanup. Add pagination, measured indexes, streaming/indexed traffic access, quotas/retention, and OAST deregistration/session expiry. Remove abort listeners after OAST sleeps resolve and avoid blocking the shared event loop with repeated synchronous RSA generation.

### I03 — P3 — Stronger runtime contracts

Plugin ambient shims reproduce only fragments of upstream types, which can let pinned-harness API drift compile. Several clients accept malformed successful HTTP responses as empty results. Validate response shapes, centralize shared types, compile/integration-test against the actual pinned harness interfaces, and surface unavailable dependencies explicitly. Preserve the existing modular dependency injection because it makes fault-path testing practical.

### I04 — P3 — Clear user-visible task lifecycle

Expose task creation, approved scope/mode, plan approval revision, active specialists, partial failures, cancellation outcome, verification status, and retained artifact locations as durable state. Distinguish “no findings,” “not executed,” “blocked,” and “incomplete verification.” Document the actual default network/security model, fresh-chat model selection behavior, supported Node/setup command, optional capability prerequisites, and how to inspect/retry failures.
