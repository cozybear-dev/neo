# Containment broker

The broker is the sole Docker socket owner. Agent plugins submit task capability tokens; the broker asks authenticated `/internal/authorize` before execution, deployment and every HTTP destination. Control/operator credentials are never injected into a worker. The agent Compose service does not load `.env` wholesale.

Workers run as UID 1000 with no capabilities, no new privileges, bounded CPU/memory/processes and rotated logs. Their mount contains only `/state/files/<task UUID>` through Docker's volume-subpath mechanism. Regular task files synchronize from the plugin, with traversal/symlink checks and bounded counts/sizes. Output is bounded and a restricted broker log is retained. Cancellation deletes the whole worker container, including descendant processes; timeout and periodic task authorization failures terminate it. Submissions are never retried automatically. Broker restart removes orphaned labeled workers.

Default worker networking is `none`. `NEO_EXEC_NETWORK=lab` joins an internal network holding only the same task's deployments. Each target's alias must still be approved before starting a worker. Internet scanners, VPN, raw privileged packet capture, USB devices, and unscoped external shell networking are deliberately unavailable. Scope-aware external HTTP is available through `/request`; each hostname, resolved address exclusions, control-plane destination and redirected request is checked, and DNS is pinned for the actual connection. Browser requests must use the interception service on the separate internal browser network.

Deployments accept image references or concrete YAML/JSON Compose files containing image, argv command, environment and expose fields only. The broker validates the concrete object again and generates container parameters itself. It rejects host paths, ports, builds, includes, secret/config mounts, arbitrary networks, privilege/capability settings and unsupported fields. Git/build-based deployment remains explicitly unavailable. Supply the endpoint service and internal HTTP port; a bounded readiness check must pass. Task ownership, actual container IDs/names, spec and lifecycle are persisted. Cleanup uses persisted ownership and reports failures; no volumes are deleted. IDs are validated before any path access.

The `/oast/callback/<idnonce.domain>` ingress accepts only bounded GET/POST bodies for the configured callback suffix and forwards to Interactsh using a validated Host header. It exposes no general forwarding or control operation. DNS OAST is unavailable without a separately configured resolver.

Run `node --test broker/policy.test.mjs broker/runtime.test.mjs`. The runtime test builds its broker image, uses disposable fixture containers/networks/volume, and exercises actual worker network denial, task files, cancellation, non-80 deployment readiness, isolated lab access and idempotent cleanup. The large sandbox image still needs a full rebuild to validate its complete locked toolchain; capability probes distinguish missing tools and unsupported modes.
